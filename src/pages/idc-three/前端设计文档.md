## 一、项目概述

### 1.1 背景与目标

构建一套**数据中心 3D 可视化监控大屏**：从全国机房态势总览逐级下钻到单个机柜的 U 位与可更换配件，覆盖"看态势 → 定位问题 → 处置闭环"的完整运维链路。

### 1.2 核心价值

| 价值 | 落点 |
|---|---|
| 空间直觉 | 三级下钻（全国 → 站点楼层 → 单机房）复刻真实物理空间，告警柜一眼定位 |
| 处置闭环 | 告警直达 → 3D 定位 → 配件更换 → 状态实时回写（不是只读大屏） |
| 资产管理 | 布局编辑器 + JSON/Excel 导入导出 + 跨房腾挪，机柜台账全生命周期 |
| 内网可部署 | 零 CDN 依赖（地图 GeoJSON 本地化、three 本地 min.js、npm 包可断网构建） |

### 1.3 需求覆盖对照（需求文档 1~11 → 模块）

| 需求点 | 承载模块 |
|---|---|
| 1/2 全国指标 + 省市下钻 | L1 全国视图（ECharts 地图） |

| 4.1 布局自定义 | M5 布局编辑器（含机柜属性编辑） |
| 4.2 数据导入导出 | M5 JSON/Excel × 整房/单柜 |
| 4.3 un- 组件穿透 | un- 组件层 + ::v-deep 规范 |

## 二、技术栈选型

| 技术 | 选型 | 选型理由 |
|---|---|---|
| 框架 | **Vue 2**（vue-cli） | 与真实项目技术栈一致，迁移零成本 |
| 样式 | **Sass + 设计令牌（CSS 变量）** | 需求 4.5：换肤只动 `styles/tokens.scss` 一处，组件层零改动 |
| 2D 图表 | **ECharts 5**（本地副本 mixin） | 地图/指标卡/KPI 成熟；GeoJSON 本地化部署内网 |
| 3D 渲染 | **three.js（vendor min.js 本地副本）** | 需求 10：内网无 npm 源；OrbitControls 相对导入改造，构建产物功能不变 |
| 电子表格 | **SheetJS（xlsx）** | 导入导出 Excel 双通道（解析与生成同一库） |
| 时间 | **dayjs** | 替代 moment（需求 4.6），体积 1/10 |
| 组件层 | **un- 前缀封装层**（el- 二次封装） | 需求 4.4：对外统一 un-button/un-select/un-dialog…，用法同 el-；样式穿透统一 `::v-deep` + `popper-class/custom-class` 挂全局类 |

**分包策略**：L1 地图首屏 chunk 仅 ~18KB；含 three 的 ~470KB 大 chunk 由楼层视图**异步组件按需加载**——不切 3D 不下载 3D。

## 三、总体架构

```
┌───────────────────── 页面/交互层（Vue 组件）─────────────────────┐
│  L1 index.vue        L1.5 FloorView.vue      L3 room/index.vue   │
│  （全国/城市/楼层切换）（楼层 3D 沙盘）      （机房 3D + 编辑/IO） │
├───────────────────── 渲染层（纯 JS，框架无关）───────────────────┤
│  NationalMap(ECharts)  floor/three/(buildFloor+FloorScene)       │
│                        room/three/(buildRoom+RoomScene+picker…)  │
├───────────────────── 数据层（api.js 统一出口）───────────────────┤
│  api.js  →  mock/（runtime SSE / rooms / floors / geo / edits）  │
│  io.js   →  导入导出解析与校验                                    │
│  model.js →  领域常量与几何公式（cellCenter/roomSize/doorCenter）│
└──────────────────────────────────────────────────────────────────┘
```

分层原则：**页面只从 api 取数、不碰 mock**；渲染层纯 JS 可单测；领域公式（坐标换算）独立成 model.js 供 3D/2D/编辑器三方共用。

## 四、页面与信息架构（三级下钻）

```
L1  /idc-three              全国地图：KPI 指标 + 省份底色 + 站点散点 + 实时告警流
 │  点击省份下钻 → 城市视图（机房点位：主入口为设备机房）
 ├── [市区点位图 | 机房建模图] 切换（需求 11，默认地图）
 │
 ├─ L1.5 楼层视图（L1 内嵌异步组件）  站点全部机房的白模沙盘：
 │     白墙房间群 + 房名/状态色 + 机柜实例色块 + 告警信标
 │     点击房间 → L3；悬停出信息卡
 │
 └─ L3  /idc-three/room?room=xx   单机房 3D 详情：
       地板网格 + 剖切白墙 + 门 + 冷通道围护 + 机柜阵列（U 位画布）
       侧栏（按需显隐）：机柜详情 + 42U 面板 → 设备配件更换
```

## 五、可视化设计

### 5.1 视觉体系（暗色大屏）

- **基调**：深藏青底（`#0A1A3C` 系）+ 青色强调（`#3DE0FF`）——大屏投影环境高对比；
- **状态色**：正常青绿 / 预警橙黄 / 告警红 / 离线灰，全局语义一致（地图点位、3D 信标、U 位块、标签同色）；
- **设计令牌**：全部颜色/字号/间距收敛为 `:root` CSS 变量（`--idc3-*`），一处换肤全局生效（需求 4.5）；
- **3D 场景配色**：机房浅色地板 + 深灰蓝柜体 + 青色网格线；楼层沙盘白色模型质感（浅灰白楼板 `#E4E9F0` + 近白墙 `#F5F7FB`）。

### 5.2 机房 3D 建模（L3）

| 元素 | 设计 |
|---|---|
| 地板网格 | 600mm 防静电地板一格一线，对齐机柜坐标（空间可读性） |
| 机柜 | 柜体 + 前脸 CanvasTexture 画 42U 占用（设备色块按类型），信标灯示警 |
| 冷通道 | 面对面排自动搭建：青绿地贴 + 深蓝半透平顶罩 + 两端深色端板 + 参差段侧封板（围护完整性） |
| 墙体 | 不透明白墙（实体围护感）+ **动态剖切**：渲染循环按相机方位隐藏朝向相机的那面墙——任何角度可见房内 |
| 门 | Room 级数据驱动（doors），琥珀金区分于青色系，双开门中缝 + 顶部标签 |
| 罗盘 | 右下角 DOM overlay，盘面随相机水平朝向实时旋转（方向语义与柜朝向/门墙体系统一：北 = -z） |

### 5.3 楼层沙盘（L1.5）

- 白模房间群照参考图形态：房间名 + 柜数 + 最严重状态色标签；
- 机柜**全站合成 1 个 InstancedMesh**（instanceColor：正常柜统一深灰蓝 / 设施柜语义色 / 异常柜状态色优先——沙盘的核心价值是"一眼看出哪片有问题"）；
- 柜体收窄 14% 留缝：远景俯视逐柜可辨（不留缝整排糊成一条线）。

### 5.4 性能设计（需求 6：千柜规模）

| 机制 | 说明 |
|---|---|
| **LOD 分档** | 机房 >80 柜自动切实例化模式（1 个 InstancedMesh 画全部柜体，无 U 位画布）；相机拉近自动换明细组（帧内按距离增删） |
| 楼层实例化 | 全站机柜恒为实例化（楼层永远是远景） |
| 悬停拾取节流 | pointermove 只记坐标，渲染循环每帧最多一次 Raycaster |
| 点击 vs 拖拽 | pointerdown 落点位移 >5px 判拖拽，不触发点击 |
| 异步分包 | three chunk 按需加载（见二） |
| 局部刷新 | 换配件只重画该柜纹理（`updateRack`），不重建场景、不丢相机 |
| 资源释放 | 全链 dispose（几何/材质/纹理/renderer/监听/ResizeObserver），路由往返零泄漏 |

兼容性：WebGL2 不可用时优雅降级——舞台出提示，侧栏功能（U 位/编辑器/导入导出）不受影响。

## 六、数据结构设计

### 6.1 核心模型：四级树（3D 渲染的唯一输入）

```
Room ── racks[] ── devices[] ── components[]
  │        │           │            │
机房      机柜        设备(U位区间)   可更换配件
```

```js
Room    { id, name, siteId, siteName, gridRows, gridCols, doors[], racks[] }
Rack    { id, name, kind(7枚举), row, col, facing(S/N), uTotal, uUsed,
          status, powerKw, loadPct, tempIn, humidity, devices[] }
Device  { id, rackId, name, category(4枚举), model, vendor, sn,
          startU, uSize, status, components[] }
Component { id(=deviceId::slot), kind(cpu/mem/disk/psu/fan), slot, model,
          status(ok/fault), replacedAt }
Doors   { wall(N/S/E/W), offset(门中心沿墙米数，从西北端量), width, label? }
```

### 6.2 坐标体系（一套语义贯穿 3D/2D/编辑器）

- **原点在机房西北角**，`col` 向东、`row` 向南，1 格 = 600mm 防静电地板；
- 世界坐标换算公式集中在 `model.js`（`cellCenter` / `roomSize` / `doorCenter` / `facingSign`），渲染层零散布公式；
- 机柜**稀疏摆放**：racks 数组里没有的格子就是空地——不满排/断行/留通道都是"少放几个"自然形成，无需额外配置。

### 6.3 站点级扩展模型

| 数据 | 用途 | 存储 |
|---|---|---|
| `floorLayout: [{roomId, x, z}]` | 楼层沙盘的房间摆放（未配置自动布局兜底） | site 级 JSON 台账 |
| `auxiliary: true` | 辅助房间（UPS间/配电间）：不出现在城市点位图与机房简表，楼层视图/直链可见 | room 表标记 |
| 设施排 `rows:[{kind}]` | 辅助房间整排 UPS/配电柜（无 U 位无设备） | mock 造数配方 |

### 6.4 设计哲学：**只存事实，推导交给渲染**

| 元素 | 性质 | 存储 |
|---|---|---|
| 机柜站哪 / 门开哪 / 房间摆哪 | **事实** | 入库（rack.row/col、doors、floorLayout） |
| 墙在哪多长 / 房间多大 | **边界**（可推导） | 不入库——由 gridRows/gridCols 推导 + 渲染常量 |
| 冷通道围护 | **布局规律**（面对面排） | 不入库——渲染层按朝向交替自动搭建 |

好处：墙/围护改形态是渲染层的事（本项目已迭代 5 版墙样式，零数据迁移）。

### 6.5 实时数据

`SSE GET /idc/metrics/stream`（2.5s/次）推送全量指标快照：KPI、站点/机房/机柜指标与状态、告警流。前端整体覆盖 `metrics` 引用（Vue 响应式链自动刷新），3D 柜色由 status 数据驱动自动跟随。

## 七、交互设计

### 7.1 浏览链路

| 交互 | 设计意图 |
|---|---|
| 单击机柜 | 选中 + 侧栏详情（**视野不动**——高频浏览不打断观察） |
| 双击机柜 | **保持当前视角的平移聚焦**：取当前视线方向平移到目标柜前，方位/俯仰零跳变，空间感连贯 |
| 悬停 | 跟随鼠标信息卡（编号/类型/U 位/功率/温度），不挡交互 |
| 定位搜索 | 下拉模糊搜索，告警/预警柜置顶；选中即 3D 高亮 + 平移聚焦 |
| 告警直达 | L1 告警流点击 → `?room=&rack=` 直飞告警柜 |
| 侧栏 | 进房默认收起（3D 全幅）→ 点机柜弹出 → 标题栏可收起 |
| 视角预设 | 总览（大房自动高俯视）/ 正视 / 俯视，相机 easeInOut 补间 |

### 7.2 管理链路（M5）

- **布局编辑器**：网格画布点格放置 / 选中移动 / 切朝向 / 删除；**属性编辑**（名称/U 位/柜型——id 系统生成不让改，防断引用）；保存前六道校验（同格冲突/编号唯一/名称非空/U 位范围/设施柜挂设备/U 位收缩）；
- **导入导出**：JSON 快照 + Excel 三 sheet（机柜布局/设备台账/门配置）× 整房全量（含 doors 落库）/ 单柜增量（同 id 覆盖或跳过、目标格被占拒绝）；模板文件见 `example/`；
- **跨房腾挪**：三步向导（选柜 → 选目标房空格 → 执行），id 不变设备配件跟随；
- **配件更换**（M4）：42U 面板点设备 → 弹框换配件 → 接口写回 → 3D 柜面局部刷新（不丢相机）。

## 八、关键技术方案备忘

| 方案 | 要点 |
|---|---|
| three 内网本地化 | vendor min.js + OrbitControls 相对导入改造；卸载 npm three，构建验证 WebGLRenderer 进 chunk |
| 动态剖切墙 | 墙轴对齐 → 相机坐标与房间边界直接比较即判定（无需向量运算），渲染循环每帧执行 |
| 双击拾取 | 浏览器原生 dblclick 事件（自带双击时序），与拖拽/单击位移判定互不干扰 |
| 相机平移聚焦 | `dir = camera.position − target` 归一化，机位 = 目标点 + dir×min(当前距离, 4.5) |
| 悬浮标签 | Sprite + CanvasTexture，始终面向相机 |
| 机房坐标 → 楼层坐标 | 楼层房间偏移 + cellCenter 复用（同一网格语义） |
| ECharts 视角保持 | 实时刷新走 `setOption(merge)` 按 series.id 命中替换，不重置用户缩放平移 |

## 九、非功能设计

- **性能基线**：L1 首屏 <20KB JS；千柜机房交互流畅（LOD 实例化）；楼层沙盘 ~20-30 draw call；
- **兼容**：现代 Chrome/Edge（WebGL2），不支持时功能降级不白屏；
- **健壮**：mock 数据确定性生成（同 id 同数据，演示可复现）；导入全量校验整单回滚；
- **规范**：ESLint 全绿；注释即文档（每个文件头部职责边界 + 关键设计决策的原因）；
- **迁移**：idc-three 文件夹自包含（数据层/组件/样式/字体全内联），拷走即用；页面只依赖 api.js 契约，接真实后端改一层。
