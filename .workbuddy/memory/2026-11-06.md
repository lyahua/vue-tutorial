## LOD 明细组真 bug 修复（用户 213 柜实测发现）
- 现象：用户把 ZH-R1 改成 7 排×30（213 柜>200 触发 LOD），点击机柜柜面 U 位不显示（柜体/名称牌正常）。
- 根因：addDetail 传给 buildRackDetail 的 track 回调写成 `obj => localDisposables.push(obj)`——push() 返回数组新长度（数字），而 buildRackDetail 用返回值赋 texture/faceMat → 柜面材质变成数字 2 → 渲染器查 material.visible 得 undefined → **静默跳过该 mesh（无报错）**。常规路径的 track 返回 obj 所以普通房间正常；STRESS-2000 当时只验证构建没浏览器实测，漏网。
- 修复：localTrack = obj => { push; return obj; }；buildRackDetail 注释写死 track 契约（必须返回对象本身）。grep 确认无同类写法。教训：LOD 路径需要真实浏览器点击验证。
